# 房间模块任务列表

> 来源：`doc/proposal.md` 5 房间系统、6 房间配置、9 房间生命周期、12 房间人数限制；`doc/detailed-design.md` 5.3 房间模块。

## 目标

交付房间创建、加入、离开、基础信息修改、人数与密码校验、房间生命周期状态维护。

## 前置约定

- 房间配置直接内嵌在 `Room` 中。
- 房间密码只存储哈希值。
- 同名房间允许重新创建，依赖新的 `roomId` 区分。

## 最小任务

- [ ] 定义 `Room` 数据结构。
- [ ] 定义 `RoomMember` 数据结构。
- [ ] 定义房间状态枚举 `ACTIVE / EMPTY / EXPIRED`。
- [ ] 定义历史策略结构 `NONE / COUNT / MINUTES`。
- [ ] 封装 `drrr:room:{roomId}` 读写删除逻辑。
- [ ] 封装 `drrr:room:members:{roomId}` 成员顺序索引读写删除逻辑，member=`userId`，score=`joinedAt`。
- [ ] 封装 `drrr:room:member-detail:{roomId}` 成员详情读写删除逻辑，field=`userId`，value=`RoomMember JSON`。
- [ ] 封装 `drrr:room:active` 活跃房间索引维护逻辑。
- [ ] 封装 `drrr:room:empty` 空房间索引维护逻辑。
- [ ] 实现创建房间请求校验：创建者存在且未处于其他房间。
- [ ] 实现创建房间请求校验：房间名必填。
- [ ] 实现创建房间请求校验：人数上限在 `1-20`。
- [ ] 实现创建房间请求校验：历史消息策略合法。
- [ ] 实现创建房间请求校验：配置修改规则合法。
- [ ] 实现房间密码哈希处理。
- [ ] 创建 `Room` 主数据，初始状态为 `ACTIVE`。
- [ ] 创建首个 `RoomMember`，创建者作为房主成员，并同时写入成员顺序索引与成员详情。
- [ ] 更新创建者 `UserSession.currentRoomId`。
- [ ] 写入 `drrr:room:active`。
- [ ] 返回房间详情。
- [ ] 实现加入房间：校验用户存在且未处于其他房间。
- [ ] 实现加入房间：校验房间存在且未过期。
- [ ] 实现加入房间：调用治理模块校验 Ban 状态。
- [ ] 实现加入房间：校验密码房密码。
- [ ] 实现加入房间：校验人数未达到上限。
- [ ] 实现加入房间：校验同房间昵称不重复。
- [ ] 写入新成员顺序索引、成员详情并更新用户当前房间。
- [ ] 若房间原状态为 `EMPTY`，恢复为 `ACTIVE` 并清空 `emptySince`。
- [ ] 加入成功后触发 `USER_JOIN` 事件。
- [ ] 加入成功后通知聊天模块生成加入系统消息。
- [ ] 加入成功后返回房间详情、成员摘要和历史消息。
- [ ] 实现主动离开房间：校验用户属于该房间。
- [ ] 主动离开时删除成员顺序索引与成员详情。
- [ ] 主动离开时清空 `UserSession.currentRoomId`。
- [ ] 主动离开时调用房主管理模块处理继承。
- [ ] 若离开后无在线成员，将房间置为 `EMPTY` 并记录 `emptySince`。
- [ ] 空房时写入 `drrr:room:empty`。
- [ ] 离开成功后触发 `USER_LEAVE` 事件。
- [ ] 空房时额外触发 `ROOM_EMPTY` 事件。
- [ ] 离开成功后通知聊天模块生成离开系统消息。
- [ ] 实现修改房间信息：校验操作者为当前房主。
- [ ] 实现修改房间信息：限制可修改字段为房间名、简介、配置项。
- [ ] 实现后续房主配置修改权限校验。
- [ ] 修改成功后刷新 `lastActiveAt`。
- [ ] 修改成功后通知聊天模块生成配置变更系统消息。

## 测试验收

- [ ] 创建房间正确初始化房主，并同时写入首成员顺序索引与成员详情。
- [ ] 人数上限只允许 `1-20`。
- [ ] 密码房密码校验正确。
- [ ] 房间满员时拒绝加入。
- [ ] 同房间昵称重复时拒绝加入。
- [ ] 被 Ban 用户无法加入。
- [ ] 空房恢复为 `ACTIVE` 时清理空房索引。
- [ ] 非房主不能修改房间。
- [ ] 后续房主无权修改配置时被拒绝。

## 完成定义

- [ ] 房间模块任务全部完成。
- [ ] 创建、加入、离开、修改房间主链路测试通过。
- [ ] 与用户会话、房主管理、治理、聊天、房间事件模块的接口约定明确。
