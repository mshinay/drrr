# 聊天模块任务列表

> 来源：`doc/proposal.md` 10 聊天系统、13 消息存储策略；`doc/detailed-design.md` 5.4 聊天模块。

## 目标

交付后端公共消息、定向消息、系统消息、历史消息保留与读取能力。

## 前置约定

- 消息类型为 `PUBLIC / DIRECT / SYSTEM`。
- 房间消息统一写入同一消息流。
- 房间事件是系统消息的事实来源，系统消息是展示结果。

## 最小任务

- [ ] 定义 `Message` 数据结构。
- [ ] 定义 `MessageView` 输出结构。
- [ ] 定义消息类型枚举 `PUBLIC / DIRECT / SYSTEM`。
- [ ] 封装 `drrr:room:messages:{roomId}` 写入读取裁剪逻辑。
- [ ] 接入 `drrr:room:{roomId}` 读取房间历史策略。
- [ ] 实现发送公共消息入口。
- [ ] 公共消息发送前校验发送者属于房间。
- [ ] 公共消息发送前校验发送者状态为 `ONLINE`。
- [ ] 公共消息发送前调用治理模块检查禁言。
- [ ] 构建 `PUBLIC` 消息并写入消息流。
- [ ] 公共消息写入后按房间历史策略裁剪。
- [ ] 公共消息写入后刷新房间 `lastActiveAt`。
- [ ] 公共消息写入后通过后端 WebSocket 通道广播给房间在线成员。
- [ ] 实现发送定向消息入口。
- [ ] 定向消息发送前校验发送者和接收者都属于房间。
- [ ] 定向消息发送前校验发送者未被禁言。
- [ ] 构建 `DIRECT` 消息，写入 `targetUserId`、`targetNickname`、`visibleTo`。
- [ ] 定向消息写入后按房间历史策略裁剪。
- [ ] 定向消息只通过后端 WebSocket 通道推送给发送者和接收者。
- [ ] 实现系统消息生成入口，接收事件类型和上下文。
- [ ] 为用户加入、离开、断线、恢复连接生成系统消息文本。
- [ ] 为房主转移生成系统消息文本。
- [ ] 为禁言、踢出、Ban 生成系统消息文本。
- [ ] 为房间配置变更生成系统消息文本。
- [ ] 系统消息写入同一消息流并通过后端 WebSocket 通道广播给房间在线成员。
- [ ] 实现历史消息读取入口。
- [ ] 历史策略为 `NONE` 时返回空列表。
- [ ] 历史策略为 `COUNT` 时读取尾部指定条数。
- [ ] 历史策略为 `MINUTES` 时按 `sentAt` 过滤时间窗口。
- [ ] 对历史消息按请求用户执行可见性过滤。
- [ ] 公共消息和系统消息对房间成员可见。
- [ ] 定向消息仅发送者和接收者可见。
- [ ] 对非法 `MINUTES` 策略值回退为空历史。

## 测试验收

- [ ] 公共消息广播给所有在线成员。
- [ ] 定向消息只对双方可见。
- [ ] 被禁言用户无法发送公共消息和定向消息。
- [ ] 系统消息进入同一聊天流。
- [ ] `COUNT` 历史策略裁剪正确。
- [ ] `MINUTES` 历史策略读取正确。
- [ ] 历史读取不会泄露不可见定向消息。

## 完成定义

- [ ] 聊天模块任务全部完成。
- [ ] 消息写入、裁剪、读取、可见性过滤测试通过。
- [ ] WebSocket 推送事件 DTO 在后端固定，供后续前端对接。
