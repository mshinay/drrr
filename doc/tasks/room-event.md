# 房间事件模块任务列表

> 来源：`doc/proposal.md` 10.4 轻量事件日志、14 聊天记录导出；`doc/detailed-design.md` 5.5 房间事件模块。

## 目标

交付房间级轻量事件日志，作为系统消息生成、状态排查和聊天记录导出的事实来源。

## 前置约定

- 每个房间维护独立事件流。
- 事件日志是运行态数据，房间销毁时同步销毁。
- `payload` 只保存事件特有补充信息，不重复公共字段。

## 最小任务

- [ ] 定义 `RoomEvent` 数据结构。
- [ ] 定义 `RoomEventView` 输出结构。
- [ ] 定义事件类型枚举：`USER_JOIN`。
- [ ] 定义事件类型枚举：`USER_LEAVE`。
- [ ] 定义事件类型枚举：`USER_RECONNECTING`。
- [ ] 定义事件类型枚举：`USER_RECONNECTED`。
- [ ] 定义事件类型枚举：`OWNER_TRANSFER`。
- [ ] 定义事件类型枚举：`USER_MUTED`。
- [ ] 定义事件类型枚举：`USER_KICKED`。
- [ ] 定义事件类型枚举：`USER_BANNED`。
- [ ] 定义事件类型枚举：`ROOM_EMPTY`。
- [ ] 定义事件类型枚举：`ROOM_EXPIRED`。
- [ ] 封装 `drrr:room:events:{roomId}` 写入读取删除逻辑。
- [ ] 实现记录事件入口，接收事件类型和上下文。
- [ ] 记录事件前校验房间存在。
- [ ] 记录事件前校验房间未销毁。
- [ ] 构建 `eventId`、`roomId`、`type`、`operatorUserId`、`targetUserId`、`payload`、`occurredAt`。
- [ ] 对上下文不完整的事件给出明确失败结果或使用空 `payload`。
- [ ] 将事件追加到房间事件流。
- [ ] 实现按房间读取事件入口。
- [ ] 读取事件时按写入顺序返回。
- [ ] 为聊天模块提供事件到系统消息生成所需上下文。
- [ ] 为导出模块提供事件列表读取能力。

## 测试验收

- [ ] 用户加入、离开、断线、恢复连接能正确写入事件。
- [ ] 房主转移能正确写入事件。
- [ ] 禁言、踢出、Ban 能正确写入事件。
- [ ] 房间进入 `EMPTY`、`EXPIRED` 能正确写入事件。
- [ ] 事件读取顺序与写入顺序一致。
- [ ] 房间不存在或已销毁时不允许追加事件。

## 完成定义

- [ ] 房间事件模块任务全部完成。
- [ ] 所有事件类型都有测试覆盖。
- [ ] 与聊天模块和导出模块的读取接口可用。
