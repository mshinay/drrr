# 大厅模块任务列表

> 来源：`doc/proposal.md` 4 大厅；`doc/detailed-design.md` 5.1 大厅模块。

## 目标

交付大厅首页所需的后端只读数据能力：最近 5 分钟活跃人数、房间列表摘要、房间排序。

## 前置约定

- 排序方式使用 `LAST_ACTIVE / MEMBER_COUNT / SURVIVAL_TIME`。
- MVP 阶段默认返回全量房间列表，不强制分页。
- 密码房只返回 `hasPassword`，不返回密码或密码哈希。

## 最小任务

- [ ] 定义大厅查询输入结构，包含排序方式和可选分页参数。
- [ ] 定义 `LobbySummary` 输出结构，包含活跃人数和房间卡片列表。
- [ ] 定义房间摘要 DTO，包含 `roomId`、名称、简介、当前人数、最大人数、是否有密码、最近活跃时间、创建时间。
- [ ] 封装 `drrr:lobby:active-users` 读取逻辑，按当前时间过滤最近 5 分钟活跃用户。
- [ ] 封装 `drrr:room:active` 读取逻辑，获取候选活跃房间 ID。
- [ ] 批量读取 `drrr:room:{roomId}` 房间主数据。
- [ ] 读取 `drrr:room:members:{roomId}` 成员数量并填充当前人数。
- [ ] 过滤房间索引存在但房间主数据缺失的脏数据。
- [ ] 实现最近活跃排序：按 `lastActiveAt` 倒序。
- [ ] 实现人数排序：按 `currentMembers` 倒序。
- [ ] 实现存活时间排序：按 `createdAt` 升序。
- [ ] 对非法排序参数回退到 `LAST_ACTIVE`。
- [ ] 暴露大厅查询接口或服务方法。
- [ ] 在后端响应 DTO 中保留 `description` 字段，供后续前端展示使用。

## 测试验收

- [ ] 活跃用户只统计最近 5 分钟窗口内的数据。
- [ ] 三种排序结果符合设计。
- [ ] 密码房响应不包含密码明文或哈希。
- [ ] 房间主数据缺失时该房间被过滤。
- [ ] Redis 读取失败时返回明确失败结果，不返回半截大厅数据。

## 完成定义

- [ ] 大厅模块任务全部完成。
- [ ] 单元测试覆盖活跃人数、排序、密码房字段隐藏、脏数据过滤。
- [ ] 与房间模块的房间数据结构字段保持一致。
